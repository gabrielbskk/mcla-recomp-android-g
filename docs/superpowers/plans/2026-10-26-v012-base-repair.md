# v0.1.2 Android Base Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the manual Android packaging path reject stale APK bases and
include the ZIP importer dependency without creating an APK in this task.

**Architecture:** `scripts/build_android_dex.sh` creates a DEX containing the
launcher and Apache Commons Compress. A small Python verifier reads Gradle's
expected package ID, Android badging, and the APK ZIP contents before manual
assembly or XAPK packaging.

**Tech Stack:** Bash, Python standard library, Android `aapt2`, D8/R8.

**Spec:** `docs/superpowers/specs/2026-10-26-v012-base-repair-design.md`

## Global Constraints

- Do not build, install, sign, publish, or delete an APK.
- Do not add game data, logs, keys, caches, or binaries to Git.
- Keep package `org.mcla.recomp.openbeta` aligned across Gradle, XAPK metadata,
  verifier and documentation.
- Do not copy code from RenanQueiroz/mcla-recomp without a separate licensing
  and Android-validation decision.

## Review Focus

- A stale APK with `org.mcla.recomp` must be rejected before packaging.
- A DEX missing `ZipArchiveInputStream` must be rejected.
- A candidate missing any of the three ARM64 runtime libraries must be rejected.
- APKs with a correct package but malformed `aapt2` output must fail closed.
- XAPK metadata must match the Open Beta app identity.
